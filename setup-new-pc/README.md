# Комплекты подключения для сотрудников

Каждый сотрудник получает **свою папку** с тремя вещами: приватный SSH-ключ,
скрипт установки и пошаговая инструкция. Папка самодостаточна — человек
распаковывает, запускает один файл и подключается.

В этом репозитории лежат только **шаблоны** (`_templates/`). Готовые папки
сотрудников содержат приватные ключи и здесь отсутствовать обязаны — см.
`.gitignore` в корне.

## Как собрать комплект

1. Заведите пользователя на сервере — `codex-add-user.sh <логин>` (или
   `codex-add-user.sh <логин> admin` для второго администратора). Скрипт создаёт
   учётку, настраивает изоляцию и печатает приватный ключ.
2. Скопируйте нужный шаблон:
   - Windows → `_templates/win/`
   - macOS → `_templates/mac/`
3. Положите в папку приватный ключ под именем `codex_<логин>_ed25519`.
4. Замените плейсхолдеры в скрипте и README: `<SERVER_IP>`, логин пользователя,
   имя файла ключа.
5. Положите в папку **отпечаток сервера** — файл `known_host.txt`:
   ```bash
   ssh-keyscan -t ed25519 <SERVER_IP> > known_host.txt   # снимать с доверенной сети
   ```
   Скрипт установки добавит строку в `~/.ssh/known_hosts` и подключится с
   `StrictHostKeyChecking=yes`. Без этого файла первое подключение принимается
   «на доверии» (`accept-new`) — рабочий, но более слабый вариант.
6. Передайте папку сотруднику **защищённым каналом** — личное облако, флешка,
   менеджер паролей. Не общим чатом.
7. Скажите сотруднику **удалить папку комплекта** после установки — скрипт
   печатает это же в конце. Ключ к тому моменту уже лежит в `~/.ssh`, а сам
   комплект остаётся вторым экземпляром пароля от сервера: во Входящих, в
   Загрузках, на флешке.

> ⚠️ Приватный ключ — это пароль от сервера. Не коммитить, не пересылать в
> мессенджерах, не класть в общие папки. При утечке — немедленно удалить
> соответствующую строку из `~/.ssh/authorized_keys` сотрудника на сервере.

## Что внутри шаблонов

| Файл | Назначение |
|---|---|
| `УСТАНОВКА.bat` / `УСТАНОВКА.command` | Точка входа для сотрудника — двойной клик |
| `setup-windows.ps1` / `setup-mac.sh` | Кладёт ключ в `~/.ssh`, правит `~/.ssh/config`, ставит права |
| `README-WINDOWS.md` / `README-MAC.md` | Инструкция: подключение, VSCode Remote-SSH, первый запуск |
| `known_host.txt` (кладёте вы) | Отпечаток сервера из `ssh-keyscan`; без него первое подключение идёт «на доверии» |

## Модель доступа

- **Обычный пользователь** — без sudo, домашняя папка `700`, rootless Docker,
  инструменты разработки ставит в свой профиль (Composer, pip+venv, npm).
  Системные пакеты (`apt`) — через администратора.
- **Администратор** — sudo без пароля, системный Docker, прямой вход под root.
  Его ключ открывает root-доступ; хранить с соответствующей осторожностью.

## Отзыв доступа

```bash
# Полностью удалить сотрудника вместе с домашней папкой
sudo deluser --remove-home <логин>

# Либо оставить данные, но закрыть вход
sudo usermod -L <логин>
sudo truncate -s 0 /home/<логин>/.ssh/authorized_keys
```

Проверьте заодно, не остались ли за ним веб-логины (дашборд расхода) и внешние
доступы — полный чек-лист offboarding в `DOCUMENTATION.md`.
